## このページの読み方

Genos は、あなたがソフトウェアを書く人だとは想定していません。以下は、仕事の種類ごとの出発点となる形です。いちばん近いものを選び、ほかは読み飛ばしてください。どれも、チャット、タスク、ノートという同じ 3 つの部品を、違う並べ方で使っています。

## エンジニア

- サービスごと、またはリポジトリごとにプロジェクトを 1 つ作ります。
- 「設定 → 連携」で GitHub を接続します。チームで Genos の GitHub アプリを使う場合は、チームのオーナーかエディターがチームに 1 回インストールし、そのあと各自が**承認する**を押します。アプリは読み取り専用で、コードにはアクセスできません。従来の方法で作った接続には、注意書きと**再接続**ボタンが表示されます。**再接続**を押すと、リポジトリ単位のより狭いアクセスに切り替わります。
- タスクを自動で完了にするには、「設定 → タスク」の**PRがマージされたら担当タスクをClose**は、新しいアカウントでは初期状態でオンです。以前に作ったアカウントは、それぞれの選択のままで、いつでも設定でオンとオフを切り替えられます。プルリクエストがマージされると、Genos はそのブランチ名に ID が含まれるタスクを完了にします(たとえばブランチ `feature/GEN-42-foo` は GEN-42 を完了にします)。完了にするのは、あなたが担当のタスクだけです。タスクに複数の PR がある場合は、最後に残っていた PR がマージされたときに完了になります。
- 依存関係は、本当にブロックしているものにだけ使います。タスク B が**によってブロックされました**でタスク A を指していると、Genos は B をブロック中にします。A が終わると、Genos は B を未着手に戻します。**タスクグラフを開く**と、マイルストーンの足を引っ張っているものが見えます。
- 設計ドキュメントはタスク自身のノートに置くと、計画が作業のそばに残ります。
- チャンネル全体を読む代わりに、Genos に聞きましょう。たとえば「今週、API プロジェクトで何が変わった?」のように。
- Claude Code などの AI アプリにタスクの作業を任せるには、「Genos を他のツールにつなぐ: API、MCP、リアルタイム」を参照してください。

## プロダクトマネージャーとプロジェクトマネージャー

- 期日のある成果にはマイルストーン、定期的なリズムにはスプリント、表計算のような見え方が必要なときにはタスクテーブルを使います。
- 同じフィルターを何度も作り直すなら、保存されたフィルターの**現在のフィルタを保存します…**を使います。保存したフィルターは、プロジェクトの全員と共有されます。
- **タスク項目をカスタマイズ**で、プロセスに必要なカスタムフィールドを追加し、必須にします。そうすると、それらがないタスクは作れません。
- ダッシュボードの**タスクの重要度**、**チームの稼働状況**、**ペース**を見ると、計画が現実的かどうか確認できます。
- 定期的な状況レポートは、「設定 → Genos → Genos Assist スケジュール」(Core 以上)で追加します。決めた時刻に、Genos がレポートを受信箱に送るか、チャットに投稿します。プロジェクトやマイルストーンの更新、チームの動き、今日やることなどのレポートがあります。
- 状況は自分でまとめず、聞きましょう。「金曜までに危ないものは?」「前のスプリントで何を完了した?」

## マーケティング

- キャンペーンごと、またはチャネルごとにプロジェクトを 1 つ作り、公開日ごとにマイルストーンを置きます。タスクには媒体(ブログ、メール、SNS、有料広告)でタグを付け、媒体ごとに絞り込みます。
- 文章の下書きは、複数人が同じドキュメントに同時に書けるノートで作ります。ブリーフは、タスクのノートの下書きの上に置きます。
- 承認は、キャンペーンのチャットで行うと、作業のそばに残ります。フォローアップが必要な決定は、タスクにします。

## リサーチと分析

- 情報源やインタビューごとにノートを 1 つ書き、調査ごとにフォルダを作ります。未解決の問いごとにタスクを 1 つ作ります。ノートには資料を、タスクにはまだ果たしていない宿題を置きます。
- Genos は、回答に使った出典を示します。引用する前に、出典をクリックして、そのノートそのものを開いて確認しましょう。
- 長いドキュメント 1 つについて質問するには、ノートのヘッダーにある質問ボタンを使います。
- 既存の資料を取り込むには、ノートの**インポート**を使います。**フォルダ全体**を選ぶと、Notion のエクスポートのようなフォルダの階層が、ノートフォルダとノートになります。

## 学生

- 授業ごとにプロジェクトを 1 つ、試験や締切ごとにマイルストーンを 1 つ、科目ごとにノートフォルダを 1 つ作ります。締切を設定すると、すべての授業が 1 つのカレンダーに載ります。
- To-Do は、授業のタスクとは別の、その日ごとのチェックリストです。勉強の時間割に向いています。
- 試験の前には、自分のノートについて聞いてみましょう。「弾性について私が書いたことを説明して」。勉強会にはグループチャットを使います。

## 運用、バックオフィス、サポート

- 繰り返しの手順は、ノートのチェックリストとして残し、実施ごとにタスクを 1 つ作ります。プロジェクトテンプレート(プロジェクトのメニュー内)を使うと、毎回同じ書き出しで始められます。
- オンボーディング、請求、ベンダーのレビューなど、プロセスごとにプロジェクトを 1 つ作ります。絶対に欠かせない情報には、必須項目を使います。
- チャットでは、**後で確認用にフラグを付ける**でメッセージを自分用のフォローアップとして残し、**リマインドする…**で好きな時刻に呼び戻します。追跡が必要な依頼は、タスクにします。
- どのタスクにも、誰がいつ何を変えたかの履歴が残ります。
- ほかのツールから作業を移すには、プロジェクトのメニューの**CSVからタスクをインポート…**を使います。CSV ファイル(Jira や Notion のデータベースのエクスポートを含む)と、Jira の JSON ファイルを読み込めます。チームのオーナーは、チームプロフィールの**Slack からインポート…**で、Slack のエクスポートをグループチャットに取り込むこともできます。

## スキルで自分の手順を繰り返す

お使いの Genos でスキルが有効なら、一連の手順を一度書いておき、あとでまた実行できます。「設定 → Genos → スキル」を開いて、スキルを作成します。スキルは自分だけのものにも、チームで共有するものにもできます。実行するには、スポットライトで質問の先頭に / を入力し、スキルを選びます。ほかの人が書いたスキル(チームスキルや Genos Hub のもの)は、インストールするとそこに表示されます。Genos Assist スケジュールで、決まった時刻にスキルを実行することもできます。その場合は公開済みのバージョンが実行され、読み取りだけを行い、何も変更しません。

## どんな仕事でも

どの場合でも、土台になるパターンは同じです。議論はチャットで、約束はタスクに、残しておきたい知識はノートに置きます。Genos はその 3 つをすべて読むので、探し回らずに聞けます。完璧な構造を作るより、まず実際のプロジェクトを 1 つ始めましょう。構造は、あとから簡単に変えられます。

## 会社全体

多くの部署がある会社で Genos を設定しますか? 「大きなワークスペースの整え方: 1 つのチームに多くの部署」と「会社で Genos を始める: オーナー向けチェックリスト」を読んでください。
